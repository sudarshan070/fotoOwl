# Decisions Log

One line per non-obvious choice, appended live during implementation — this feeds the README's "what was cut and why" section directly, so it's written in the moment, not reconstructed at the end.

- **2026-08-08 — Scope cut: web track only.** `media-native` and `media-ui-native` are not implemented in this pass. The spec's app deliverable is React web; building both platforms in the same ~9hr budget would have thinned every layer rather than delivering two solid ones. `media-core`'s API and the `media-ui-react` prop-getter shapes are designed so a native wrapper/component pair could be added later without changing either. Confirmed with the requester before starting implementation.
- **2026-08-08 — useLightbox ships a simplified focus model, not a full cyclic focus trap.** Focus moves into the dialog on open and Escape/Arrow keys work via a document-level listener, but Tab does not yet wrap from the last focusable element back to the first. Full trap cycling was cut for time; the prop-getter shape (`getOverlayProps` returning `ref`/`role`/`aria-modal`/`tabIndex`) doesn't need to change to add it later.
- **2026-08-09 — Dogfooding `skill-wiring-data.md` and `skill-using-components.md`: one real mismatch found and corrected, plus one real gotcha hit and documented.** Writing the two skill docs against the completed `SearchPage`/`LightboxOverlay`/`ReelsView` code (Tasks 1-3) rather than from memory turned up:
  - **Mismatch (fixed in `skill-wiring-data.md`):** the drafted doc claimed "all three" data hooks (`useMediaSearch`, `useCuratedMedia`, `useMediaItem`) return the same `{ items, loading, error, hasMore, loadMore }` shape. That's wrong — only the first two do. `useMediaItem` is not paginated and actually returns `{ item, loading, error }` (see `packages/media-react/src/use-media-item.ts`). Corrected the doc to call out `useMediaItem`'s distinct shape explicitly instead of lumping it in.
  - **Real gotcha hit during Task 3 (documented in `skill-using-components.md`'s `useLightbox` section):** `useLightbox` never reconciles `currentIndex` when the `items` array it was given shrinks. Submitting a new search query while the lightbox was open (commit `8cef896`) left a stale `currentIndex` pointing past the end of the new, shorter results array, crashing on `currentItem.type`. Fixed in `SearchPage.tsx` by closing the lightbox on every new search submission, and added this as an explicit caution in the skill doc so the next consumer resets/closes anything keyed off an index whenever the underlying `items` can change out from under it.
  - Everything else checked — `MediaProvider`/`useMediaClient` ownership of the single client, `useMediaSearch`/`useCuratedMedia` param-serialization-not-identity refetch keying, `useMediaEvents`/`useTrackMediaEvent` subscribe/unsubscribe and default console logging, and every `useGrid`/`useLightbox`/`useReelSwiper` prop-getter name, shape, and documented cut (sentinel-must-be-rendered, disabled boundaries, no Tab-trap, scroll-snap style merging, IntersectionObserver height/overflow requirement) — matched the real implementation in `packages/media-react/src` and `packages/media-ui-react/src` exactly, since both were written from the same frozen `ARCHITECTURE.md` signatures.
